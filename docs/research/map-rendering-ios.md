# Map engine and tile source for ABRP-native (iOS)

Research for issue #4. Compares **MapLibre Native iOS** (Metal renderer) and **Apple MapKit** on the axes the issue lists, then tile-source licensing/cost, and what Google Maps documents about its own rendering. Every claim carries the URL it was read from; facts checked 2026-08-27.

Terms follow `CONTEXT.md`: *Charger* (data object), *Plan*, *Leg* (road geometry), *Charging Stop*.

## 1. Summary / decision facts

| Axis | MapLibre Native iOS | Apple MapKit |
|---|---|---|
| Custom vector tiles + custom style | Yes: renders any MapLibre Style JSON over MVT vector tiles; you choose the tile server ([style spec](https://maplibre.org/maplibre-style-spec/)) | No vector tile input. `MKTileOverlay` is "an overlay that covers an area of the map with tiles of **bitmap** images"; styling is limited to `MKStandardMapConfiguration` emphasis/elevation/POI/traffic ([MKTileOverlay](https://developer.apple.com/documentation/mapkit/mktileoverlay), [MKStandardMapConfiguration](https://developer.apple.com/documentation/mapkit/mkstandardmapconfiguration)) |
| Renderer | Metal since iOS v6.0.0 (Jan 2024); legacy renderer removed in 6.13.0; current ios-v6.29.0 ([CHANGELOG](https://github.com/maplibre/maplibre-native/blob/main/platform/ios/CHANGELOG.md), [news](https://maplibre.org/news/2024-01-19-metal-support-for-maplibre-native-ios-is-here/)) | Apple-internal (not documented) |
| Thousands of Chargers | GPU symbol/circle layers from an `MLNShapeSource` with built-in clustering (`MLNShapeSourceOptionClustered`, `ClusterRadius` default 50, `ClusterMinPoints` default 2, `ClusterProperties` aggregation) ([MLNShapeSource.h](https://github.com/maplibre/maplibre-native/blob/main/platform/darwin/src/MLNShapeSource.h)) | UIView-based annotation views with reuse queue; automatic clustering via `clusteringIdentifier` / `MKClusterAnnotation` (iOS 11+) ([clusteringIdentifier](https://developer.apple.com/documentation/mapkit/mkannotationview/clusteringidentifier), [MKClusterAnnotation](https://developer.apple.com/documentation/mapkit/mkclusterannotation)). SwiftUI `Map` (`Annotation`/`Marker`, iOS 17) documents no clustering API ([Annotation](https://developer.apple.com/documentation/mapkit/annotation)) |
| 120 Hz ProMotion | `preferredFramesPerSecond` (arbitrary integer, default adaptive); 120 fps support since 4.5.0; app must set `CADisableMinimumFrameDuration` (6.6.0 note) ([MLNMapView.h](https://github.com/maplibre/maplibre-native/blob/main/platform/ios/src/MLNMapView.h), [CHANGELOG](https://github.com/maplibre/maplibre-native/blob/main/platform/ios/CHANGELOG.md), [Apple ProMotion doc](https://developer.apple.com/documentation/quartzcore/optimizing-promotion-refresh-rates-for-iphone-13-pro-and-ipad-pro)) | No public frame-rate API on `MKMapView`/`Map` ([MKMapView](https://developer.apple.com/documentation/mapkit/mkmapview)) |
| Offline | `pmtiles://` (6.10.0, ambient cache 6.27.0), `mbtiles://` file source (5.10.0), offline packs (`MLNOfflineStorage`) ([CHANGELOG](https://github.com/maplibre/maplibre-native/blob/main/platform/ios/CHANGELOG.md)) | None for the basemap; only raster `MKTileOverlay` you supply yourself ([MKTileOverlay](https://developer.apple.com/documentation/mapkit/mktileoverlay)) |
| SwiftUI | Official docs: wrap `MLNMapView` in `UIViewRepresentable`; separate `maplibre/swiftui-dsl` package (iOS 15+, pre-1.0, BSD-3) ([Getting started](https://github.com/maplibre/maplibre-native/blob/main/platform/ios/MapLibre.docc/GettingStarted.md), [swiftui-dsl](https://github.com/maplibre/swiftui-dsl)) | First-party `Map` with `MapContentBuilder`, `Marker`, `Annotation`, `MapPolyline`, `MapStyle` (iOS 17) ([MapKit for SwiftUI](https://developer.apple.com/documentation/mapkit/mapkit-for-swiftui)) |
| Engine licence/cost | BSD 2-Clause; tiles cost separately ([LICENSE](https://github.com/maplibre/maplibre-native/blob/main/LICENSE.md)) | Native MapKit has no published price; MapKit **JS** is capped at 250,000 map views/day free ([Apple Maps on the Web](https://developer.apple.com/maps/web/)) |

**Bottom line for the engine choice.** The issue's hard requirements (custom vector tiles/styles, offline PMTiles/MBTiles, an explicit 120 Hz path, GPU-side clustering of thousands of Chargers) are only satisfied by MapLibre Native. MapKit wins only on zero-config SwiftUI and zero tile cost, and cannot render a custom vector basemap at all.

**Bottom line for the tile source.** Self-hosted **Protomaps PMTiles** (planet ≈120 GB, daily builds, ODbL + attribution) or **Planetiler → OpenMapTiles-schema PMTiles** are the only options that permit unrestricted offline extraction. Among hosted providers, **Stadia Maps** is the only one whose Terms explicitly allow offline caching (≤100 MB/device); **MapTiler** forbids bulk download; **Protomaps API** is $14/month commercial up to 1 M tiles/month.

## 2. MapLibre Native iOS

### 2.1 Renderer and versions

- Current release: **ios-v6.29.0** (23 Aug 2026), preceded by 6.28.0 (23 Jul). Source: [GitHub releases](https://github.com/maplibre/maplibre-native/releases).
- 6.0.0: "This is the first release that uses **Metal** for rendering. This is a graphics API from Apple that replaces OpenGL ES on Apple platforms." Source: [platform/ios/CHANGELOG.md](https://github.com/maplibre/maplibre-native/blob/main/platform/ios/CHANGELOG.md).
- Metal announced January 2024: "With the new Metal rendering backend we are no longer exposed to this risk and users will benefit from the advantages of a state-of-the-art graphics framework." Sponsored by AWS and Meta. Source: [maplibre.org news 2024-01-19](https://maplibre.org/news/2024-01-19-metal-support-for-maplibre-native-ios-is-here/).
- 6.13.0: "Remove legacy renderer from source, build files and CI … Should have no impact on iOS since releases were already using the new drawable renderer architecture since 6.0.0." Source: [CHANGELOG](https://github.com/maplibre/maplibre-native/blob/main/platform/ios/CHANGELOG.md).
- Roadmap status: Metal "Released: January 2024", Vulkan "Released: December 2024", WebGPU "Released: October 2025". Source: [MapLibre Native roadmap](https://maplibre.org/roadmap/maplibre-native/).
- 6.5.0: "Allow using MapLibre Native on iPad Air 2. Note: test your styles! iPad Air 2 has one of the oldest GPUs that support Metal." Source: [CHANGELOG](https://github.com/maplibre/maplibre-native/blob/main/platform/ios/CHANGELOG.md).
- Distribution: Swift package `maplibre-gl-native-distribution` is a single `binaryTarget` pointing at `MapLibre.dynamic.xcframework.zip` of ios-v6.29.0. Source: [Package.swift](https://github.com/maplibre/maplibre-gl-native-distribution/blob/main/Package.swift).
- Licence: BSD 2-Clause. Source: [LICENSE.md](https://github.com/maplibre/maplibre-native/blob/main/LICENSE.md).
- No first-party FPS benchmarks were found on maplibre.org or in the release notes; the Metal announcement gives none. MapTiler's [SDK benchmark](https://labs.maptiler.com/sdk-benchmarks/) is web-only (Lighthouse) and reports no fps. Treat 120 Hz smoothness as *unverified until measured on device* (see §6).

### 2.2 Custom vector tiles and styles

- A MapLibre style "is a document that defines the visual appearance of a map: what data to draw, the order to draw it in, and how to style the data when drawing it" — sources, layers, expressions. Source: [MapLibre Style Spec](https://maplibre.org/maplibre-style-spec/).
- The DocC landing page lists articles including *PMTiles*, *GeoJSON*, *Tile URL Templates*, *Custom Style Layer Example* (custom Metal shaders), *Offline Pack Example*, *Manage Offline Regions*, *Rendering Statistics Hud*, *Plugin Layers*. Source: [MapLibre.docc/MapLibre.md](https://github.com/maplibre/maplibre-native/blob/main/platform/ios/MapLibre.docc/MapLibre.md).
- 6.29.0: "Changes to the custom Metal layer to allow more flexible rendering" (#4446); earlier "Addition of an MLNCustomStyleLayer that allows running custom Metal shaders and code" (#2006). Source: [CHANGELOG](https://github.com/maplibre/maplibre-native/blob/main/platform/ios/CHANGELOG.md). Relevant if a Leg's SoC-coloured polyline is ever moved to a custom shader.

### 2.3 Route polyline and Charger markers (clustering)

- `MLNShapeSource` clustering options (verbatim from the header):
  - `MLNShapeSourceOptionClustered`
  - `MLNShapeSourceOptionClusterRadius`: "specifies the radius of each cluster if clustering is enabled. A value of 512 produces a radius equal to the width of a tile. The default value is 50."
  - `MLNShapeSourceOptionClusterMinPoints`: "specifies the minimum number of points to form a cluster if clustering is enabled. The default value is 2." (added 6.17.0)
  - `MLNShapeSourceOptionClusterProperties`: dictionary of aggregated attributes, "The dictionary value is an NSArray consisting of two NSExpression objects." (added 5.x from Mapbox #15515) — usable to aggregate e.g. max power per cluster of Chargers.
  - `MLNShapeSourceOptionMaximumZoomLevelForClustering`: "Defaults to one zoom level less than the value of MLNShapeSourceOptionMaximumZoomLevel so that, at the maximum zoom level, the shapes are not clustered."
  - Cluster inspection: `leavesOfCluster:offset:limit:`, `childrenOfCluster:`, `zoomLevelForExpandingCluster:`; queries return `MLNPointFeatureCluster`.
  Source: [MLNShapeSource.h](https://github.com/maplibre/maplibre-native/blob/main/platform/darwin/src/MLNShapeSource.h), [CHANGELOG](https://github.com/maplibre/maplibre-native/blob/main/platform/ios/CHANGELOG.md).
- UIView annotations vs style layers: the changelog records Metal-specific costs for `MLNAnnotationView`: 6.3.0 "Temporary workaround for map display freeze / stutter when using annotation views with Metal backend" and 6.4.1 "Synchronous rendering on Metal when annotation views are visible." Source: [CHANGELOG](https://github.com/maplibre/maplibre-native/blob/main/platform/ios/CHANGELOG.md). Implication: render Chargers as a clustered symbol/circle layer, and reserve `MLNAnnotationView` for the selected Charging Stop callout only.
- Polylines: line layers are style layers (see *Line Style Layer Example*, *Animated Line Example*, *POI Along Route Example* in the [DocC index](https://github.com/maplibre/maplibre-native/blob/main/platform/ios/MapLibre.docc/MapLibre.md)); a Leg's geometry can be styled per-feature via data-driven expressions (*DDS Circle Layer Example* shows the pattern).

### 2.4 120 Hz ProMotion

- `MLNMapView.preferredFramesPerSecond`: "The default value for this property is MLNMapViewPreferredFramesPerSecondDefault, which will adaptively set the preferred frame rate based on the capability of the user's device to maintain a smooth experience. In addition to the provided MLNMapViewPreferredFramesPerSecond options, this property can be set to arbitrary integer values. @see CADisplayLink.preferredFramesPerSecond". Source: [MLNMapView.h](https://github.com/maplibre/maplibre-native/blob/main/platform/ios/src/MLNMapView.h).
- 4.5.0: "Added support for 120 frames per second on capable devices." Source: [CHANGELOG](https://github.com/maplibre/maplibre-native/blob/main/platform/ios/CHANGELOG.md).
- 6.6.0: "Fixed annotation delay in demo app for 120Hz devices … The issue is only present on devices with ProMotion (120Hz) displays and can be fixed by updating the Info.plist for your app". Source: [CHANGELOG](https://github.com/maplibre/maplibre-native/blob/main/platform/ios/CHANGELOG.md).
- Apple requirement: add `CADisableMinimumFrameDuration = true` to Info.plist and use `CADisplayLink.preferredFrameRateRange` to reach 120 Hz; the system may still lower rates for thermal/battery reasons. Source: [Optimizing ProMotion refresh rates](https://developer.apple.com/documentation/quartzcore/optimizing-promotion-refresh-rates-for-iphone-13-pro-and-ipad-pro).
- 6.28.0/6.29.0 include a fix for a "feedback loop under iOS 26 Smart Display Zoom" from rewriting `contentScaleFactor/drawableSize` every layout pass (#4251, CarPlay). Source: [CHANGELOG](https://github.com/maplibre/maplibre-native/blob/main/platform/ios/CHANGELOG.md).

### 2.5 Offline tiles (PMTiles / MBTiles)

- 6.10.0: "Add support for PMTiles with `pmtiles://` URL scheme (#2882)". 6.27.0: "Implement ambient cache for PMTiles sources (#4290)". 6.29.0 hardens PMTiles metadata decompression failures (#4399); 6.2x "Force PMTiles metadata to always have XYZ tile scheme" (#3403). Source: [CHANGELOG](https://github.com/maplibre/maplibre-native/blob/main/platform/ios/CHANGELOG.md).
- 5.10.0: "Added the mbtiles file source for rendering vector tiles from file stored locally on the device." Source: [CHANGELOG](https://github.com/maplibre/maplibre-native/blob/main/platform/ios/CHANGELOG.md).
- Offline packs (`MLNOfflineStorage`) are documented under *Offline Pack Example* / *Manage Offline Regions Example*. Source: [DocC index](https://github.com/maplibre/maplibre-native/blob/main/platform/ios/MapLibre.docc/MapLibre.md).
- PMTiles format: "a single-file archive format for pyramids of tiled data"; "PMTiles readers use HTTP Range Requests to fetch only the relevant tile or metadata inside a PMTiles archive on-demand". Spec is CC0/public domain, reference implementations BSD-3. Source: [docs.protomaps.com/pmtiles](https://docs.protomaps.com/pmtiles/), [protomaps/PMTiles](https://github.com/protomaps/PMTiles).

### 2.6 SwiftUI integration maturity

- Official guide creates a SwiftUI project and says: "To use MapLibre with SwiftUI we need to create a wrapper for the UIKit view that MapLibre provides (using UIViewRepresentable." Source: [GettingStarted.md](https://github.com/maplibre/maplibre-native/blob/main/platform/ios/MapLibre.docc/GettingStarted.md).
- `maplibre/swiftui-dsl` ("MapLibreSwiftUI"): "Swift DSLs for MapLibre Native … to enable better integration with SwiftUI"; pre-1.0, "robust for the subset of the MapLibre iOS API that it supports"; iOS-only; BSD-3; originated at Stadia Maps / Ferrostar, now under the MapLibre org. `Package.swift`: `platforms: [.iOS(.v15), .macOS(.v12)]`, depends on `maplibre-gl-native-distribution` from 6.21.2, swift-tools-version 6.2. Source: [README](https://github.com/maplibre/swiftui-dsl), [Package.swift](https://github.com/maplibre/swiftui-dsl/blob/main/Package.swift).
- Stadia's iOS quickstart: "MapLibre Native integrates easily into SwiftUI with the MapLibre SwiftUI DSL." Source: [docs.stadiamaps.com](https://docs.stadiamaps.com/native-multiplatform/maplibre-gl-native/).
- Maturity read: the core SDK is UIKit/Obj-C (`MLN*`), SwiftUI is a thin community DSL without API-stability promise. Budget for owning a `UIViewRepresentable` wrapper.

## 3. Apple MapKit

- `MKMapView`: "An embeddable map interface, similar to the one that the Maps app provides." iOS 3+. Configuration via `preferredConfiguration` (iOS 16+) with `MKStandardMapConfiguration` / `MKHybridMapConfiguration` / `MKImageryMapConfiguration`. Source: [MKMapView](https://developer.apple.com/documentation/mapkit/mkmapview), [preferredConfiguration](https://developer.apple.com/documentation/mapkit/mkmapview/preferredconfiguration).
- Styling surface = `emphasisStyle`, `elevationStyle`, `pointOfInterestFilter`, `showsTraffic` only. No custom style or tile-source hook. Source: [MKStandardMapConfiguration](https://developer.apple.com/documentation/mapkit/mkstandardmapconfiguration).
- Custom tiles: `MKTileOverlay` — "An overlay that covers an area of the map with tiles of bitmap images"; URL template with x/y/z/scale; `canReplaceMapContent`, `tileSize`, `minimumZ`/`maximumZ`; iOS 7+. Raster only. Source: [MKTileOverlay](https://developer.apple.com/documentation/mapkit/mktileoverlay).
- Overlay z-order is limited to two levels: `aboveRoads` ("above roadways but below map labels") and `aboveLabels`. Source: [MKOverlayLevel](https://developer.apple.com/documentation/mapkit/mkoverlaylevel).
- Clustering (UIKit): "Clustering occurs when there's a collision between multiple annotation views with the same identifier on the map surface. MapKit removes the annotation views involved in the collision … and replaces them with a clustering annotation view". iOS 11+. Customise via `mapView(_:clusterAnnotationForMemberAnnotations:)`. Source: [clusteringIdentifier](https://developer.apple.com/documentation/mapkit/mkannotationview/clusteringidentifier), [MKClusterAnnotation](https://developer.apple.com/documentation/mapkit/mkclusterannotation).
- Annotation views are UIViews with a reuse queue (`register(_:forAnnotationViewWithReuseIdentifier:)`, `dequeueReusableAnnotationView`). Source: [MKMapView](https://developer.apple.com/documentation/mapkit/mkmapview). Thousands of Chargers therefore means thousands of view objects unless clustered; there is no GPU symbol-layer path.
- SwiftUI: `Map` (iOS 14+; content-builder form with `Marker`, `Annotation`, `MapPolyline`, `MapCircle`, `MapPolygon`, `MapStyle`, camera types, controls is iOS 17+). `Annotation` and `MapPolyline` docs list no clustering or performance guidance. Source: [MapKit for SwiftUI](https://developer.apple.com/documentation/mapkit/mapkit-for-swiftui), [Map](https://developer.apple.com/documentation/mapkit/map), [Annotation](https://developer.apple.com/documentation/mapkit/annotation), [MapPolyline](https://developer.apple.com/documentation/mapkit/mappolyline), [MapStyle](https://developer.apple.com/documentation/mapkit/mapstyle).
- Frame rate: no `preferredFramesPerSecond`-type property is documented on `MKMapView` or `Map` (searched the class topic lists above). ProMotion behaviour is whatever the system view does.
- Cost: Apple publishes limits only for the web/server products: "250,000 map views and 25,000 service calls per day per Apple Developer Program membership" for MapKit JS; snapshots 25,000/day. No price or cap is published for native MapKit. Source: [Apple Maps on the Web](https://developer.apple.com/maps/web/). (Forum thread [743284](https://developer.apple.com/forums/thread/743284) has only a non-Apple self-answer saying native use is free; not an official statement.)

## 5. What Google Maps iOS documents about feeling fast

Only the following is documented; Google publishes no renderer internals for the iOS SDK.

- Vector tiles since Maps 5.0 (Dec 2010): "Maps will download 'vector tiles' that describe the underlying geometry of the map"; needs "more than 100 times less data to view maps across all zoom levels than before", which enables caching for "poor—or no—network connections" and 3D buildings drawn from footprints and heights. Source: [Google Mobile Blog, "Under the hood of Google Maps 5.0 for Android"](http://googlemobile.blogspot.com/2010/12/under-hood-of-google-maps-50-for.html).
- iOS SDK renderer: Metal opt-in from v5.2.0 (`GMSServices.setMetalRendererEnabled(true)`), default from v8.0.0, OpenGL deprecated v9.0.0; v10.14.0 "Optimized the underlying map styling data to improve load latency and reduce initial data payload"; current 11.0.0 (Aug 2026). Source: [Maps SDK for iOS release notes](https://developers.google.com/maps/documentation/ios-sdk/release-notes).
- Frame rate: `GMSMapView.preferredFrameRate` "Default value is kGMSFrameRateMaximum"; `kGMSFrameRateMaximum` = "the maximum frame rate for a device. For low end devices this will be 30 FPS, for high end devices 60 FPS" — i.e. Google's SDK documents **60 fps**, not 120. Source: [GMSMapView](https://developers.google.com/maps/documentation/ios-sdk/reference/objc/Classes/GMSMapView), [GMSFrameRate](https://developers.google.com/maps/documentation/ios-sdk/reference/objc/Enums/GMSFrameRate).
- Markers: a texture atlas for `icon` markers ("Adding a large number of markers with unique, dynamic, or high-resolution custom images can exhaust the Maps SDK for iOS's internal texture cache"; reuse the same `UIImage`); `iconView` UIView markers are "demanding on resources when tracksViewChanges is set to YES"; Advanced Markers add `GMSCollisionBehavior` (`Required`, `RequiredAndHidesOptional`, `OptionalAndHidesLowerPriority`) with zIndex priority. Source: [Markers](https://developers.google.com/maps/documentation/ios-sdk/marker), [GMSCollisionBehavior](https://developers.google.com/maps/documentation/ios-sdk/reference/objc/Enums/GMSCollisionBehavior), [Collision behavior](https://developers.google.com/maps/documentation/ios-sdk/advanced-markers/collision-behavior).
- Take-away: the documented ingredients of "fast" are (1) vector tiles with a small payload, (2) a GPU (Metal) renderer, (3) atlas-textured markers with collision-based hiding instead of per-marker UIViews. MapLibre Native offers all three (vector MVT, Metal, symbol layers with built-in collision/clustering); MapKit exposes only (1)/(2) on Apple's own data with UIView annotations.
