# Imported OBDb data -- attribution and provenance

Everything under `data/imported/obdb/` is imported from [OBDb](https://github.com/OBDb), a
community reverse-engineering project, and is licensed **CC-BY-SA-4.0** (see `LICENSE` in this
directory) -- separately from the rest of this repository, which is MIT (root `LICENSE`). None of
these files are hand-edited; they are tool output, regenerated by `import_obdb_vectors` (see below).

Wayfinder ticket: [#77](https://github.com/arodroz/abrp/issues/77). Format decision: ADR 0013
(`docs/adr/0013-telemetry-profile-format.md`), licensing lane 2.

## What's imported, and what isn't

Only OBDb's recorded **test vectors** (`tests/test_cases/<year>/commands/*.yaml`: real multi-frame
CAN responses plus their expected decoded values) are imported, for vector-validating this repo's
own decoder against real recorded car traffic. OBDb's `signalsets/v3` JSON (the decode-rule
definitions themselves) is **not** imported -- ADR 0013 point 4 defers bulk signalset import until
something consumes it, and in any case the DIDs/bit-offsets/scalings those files encode are facts,
not copyrightable expression, so `data/profiles/*.tprof.json` authors them fresh under this repo's
own MIT license rather than importing OBDb's file.

## Regenerating

Clone OBDb's vehicle repo to a **temp directory outside this repo** (never commit the clone itself),
then run the importer (feature-gated so a normal build never pulls in its YAML dependency):

```bash
git clone https://github.com/OBDb/Hyundai-IONIQ-5.git /tmp/obdb-hyundai-ioniq5
cargo run -p telemetry --bin import_obdb_vectors --features import-tools -- \
  --repo /tmp/obdb-hyundai-ioniq5 \
  --source-url https://github.com/OBDb/Hyundai-IONIQ-5 \
  --year 2023 \
  --out data/imported/obdb/hyundai-ioniq5 \
  --count 6 \
  7E4.7EC.220101 7E4.7EC.220102 7E4.7EC.220103 7E4.7EC.220104 7E4.7EC.22010A 7E4.7EC.22010B \
  7E4.7EC.22010C 7E4.7EC.220105 7E4.7EC.220111 7C6.7CE.22B002 7E5.7ED.22E011
```

`--count` caps how many of a command's (sometimes 100+) recorded test cases are imported per file;
6 was chosen for genuine signal-value diversity (varying SoC, positive/negative current, distinct
cell numbers) without vendoring OBDb's entire, much larger test corpus.
